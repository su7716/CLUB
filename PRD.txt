# PRD: 원우회 송년 워크숍 앱

> 이 문서는 바이브코딩 도구(Claude Code, Cursor 등)에 그대로 넣어 앱을 만들기 위한 PRD입니다.
> 배포 대상은 **Vercel**입니다. 먼저 "6. 기술 스택"과 "13. 구현 순서"를 읽고, 단계별로 하나씩 만들어 주세요.

## 1. 배경과 목표

- **행사**: 조선일보 CEO AI 초격차 교육 수료자 원우회의 첫 송년회·워크숍 (12월 11일~12일, 대명 홍천 소노펠리체, 약 20명)
- **참석자**: 주로 50~60대 대표, 일부 30~40대 대표. 앱이 익숙하지 않은 분을 기준으로 한다.
- **목표**: 휴대폰 하나로 서로를 알아가는 3가지 활동을 진행하고, 행사 후에도 쓰는 회원 프로필 북을 남긴다.
  1. **내가 누굴까요?** (별칭 소개글 맞히기 + 2진실 1거짓)
  2. **나의 고민은?** (고민 뽑기와 대화)
  3. **타임캡슐** (1년 뒤 목표와 팀 약속을 봉인)
- **성공 기준**: 참석자 20명이 앱 설치·가입 없이 QR로 접속해 사전 작성을 마치고, 현장에서 사회자 화면과 휴대폰이 끊김 없이 동기화된다.

## 2. 사용자와 역할

| 역할 | 설명 | 인증 |
|---|---|---|
| 관리자 (사회자) | 사무총장. 설정, 현장 진행, 열림 일시 등록 | 관리자 비밀번호 |
| 회원 | 사전 등록된 원우회 회원 | 명단에서 이름 선택 + 초대코드 |

- 회원가입, 이메일, 소셜 로그인은 **없다.**
- 사회자 화면은 프로젝터나 큰 화면에 띄우는 **전체화면 모드**를 지원한다.

## 3. 디자인 원칙

- **모바일 우선** (세로 화면 360~430px 기준). 글자는 기본 18px 이상, 버튼은 높이 52px 이상.
- 한 화면에 하나의 행동만 둔다. 설명은 짧게, 한국어로만 제공한다.
- 스타일: 크림색 배경(#F3EDE3), 갈색 포인트(#8A5A33), 세리프 서체(Noto Serif KR), 얇은 테두리 카드. 라이트 모드만 지원해도 된다.
- 접근성: 명도 대비 4.5:1 이상, 확대해도 레이아웃이 깨지지 않을 것.
- 로딩, 빈 상태, 오류 상태를 모든 화면에 만든다.

## 4. 범위

**포함**: 위 3개 활동, 회원 명단, 졸업여행 참석 확인, 프로필 북, 관리자 화면, AI 인터뷰, 음성 입력, 명리 풀이(선택).
**제외**: 결제, 푸시 알림, 채팅방 간 메시지, 다국어, 네이티브 앱, 회원 간 DM.

## 5. 화면과 핵심 흐름

### 5.1 공통

**접속과 로그인**
- 접속 방법: QR/링크 → 이름 선택(명단) → 초대코드 입력.
- 초대코드는 모든 회원이 같은 값을 쓴다(관리자가 설정). 로그인 성공 시 서명된 세션 쿠키(30일)를 발급한다.
- 5회 연속 틀리면 1분간 잠금한다.

**졸업여행 참석 팝업 (첫 접속 시 1회)**
- 문구: "졸업여행에 참석하시나요?"
- 선택지(복수 선택 가능): **12월 11일 / 12월 12일 / 참석안함**
- 안내문: "1박 2일 참석하시면 두 날짜를 모두 눌러 주세요."
- 규칙: 참석안함을 누르면 날짜 선택이 해제되고, 날짜를 누르면 참석안함이 해제된다. 하나도 고르지 않으면 확인 버튼이 비활성화된다.
- 날짜를 하나 이상 고른 회원에게 **"졸업여행 참석자"** 라벨을 붙이고, 선택한 날짜(11일 / 12일 / 11~12일)를 함께 표시한다. 명단과 "누구일까?" 선택 목록에 라벨을 보여 준다.
- 나중에 설정 화면에서 바꿀 수 있고, 관리자도 수정할 수 있다.

**개인정보 동의 (첫 접속 시 1회)**
- 문구: "작성하신 내용 중 본인이 공개로 선택한 부분은 원우회 회원들에게 보여집니다. 언제든 수정·삭제할 수 있습니다."
- 동의하지 않으면 활동 기능을 사용할 수 없다.

**홈**
- 카드 4개: 내가 누굴까요? / 나의 고민은? / 타임캡슐 / 회원 프로필 북
- 각 카드에 상태 배지(미작성, 작성 중, 승인 완료 등)를 표시한다.

### 5.2 활동 ① 내가 누굴까요?

**일정 (관리자가 날짜를 설정하며, 각 단계는 시작·마감 일시를 가진다)**

| 단계 | 시점 | 내용 |
|---|---|---|
| 작성 | 행사 2주 전 오픈 ~ 1주 전 마감 | AI 인터뷰로 소개 작성 |
| 추측 | 행사 1주 전 ~ 전날 | 다른 회원 별칭 소개글을 읽고 누구인지 선택 |
| 현장 | 행사 당일 | 사회자 진행 |

**A. 사전 작성 (AI 인터뷰)**
1. **별칭 정하기**: 이름과 회사명이 드러나지 않아야 하며, 다른 회원과 중복될 수 없다.
2. **AI 채팅 인터뷰**
   - 채팅 UI로 진행한다. AI는 **관리자가 작성한 지침(system prompt)** 에 따라 질문한다.
   - 필수 질문(관리자가 편집 가능): 유년시절의 기억, 특이한 경험, 인생의 터닝포인트, 성공 또는 실패 경험, 삶의 기준이나 철학, 취미, 좋아하는 것, 싫어하는 것.
   - 필수 질문 후 AI가 후속 질문을 **최대 6개**까지 이어서 한다. 약 10분 안에 끝낼 수 있어야 한다.
   - **금지 규칙**: 이름, 회사명, 직함, 업종, 출신 학교 등 신원을 바로 알 수 있는 정보는 묻지도 쓰지도 않는다. 답변에 들어 있으면 생성 단계에서 제거하거나 일반화한다(회사명 → "한 회사").
   - 중간 저장과 이어쓰기를 지원한다.
3. **음성 입력**
   - 입력창 하단에 **음성 버튼**을 둔다. 누르고 말하면 음성이 인식되어 **텍스트로 입력창(또는 채팅창)에 표시**되고, 사용자가 확인·수정 후 전송한다.
   - 기본은 브라우저 Web Speech API(`lang="ko-KR"`). 지원되지 않거나 실패하면 **서버 음성인식 API로 폴백**하거나, 키보드 입력으로 바로 전환하는 안내를 보여 준다.
   - 마이크 권한 안내와 거부 시 안내 문구를 제공한다.
4. **결과 생성**
   - 소개 페이지(약 2페이지 분량, 한국어)와 **2진실 1거짓 후보**를 생성한다.
   - 2진실 1거짓은 **소개 페이지에 쓰지 않은 내용**으로 만들고, 너무 뻔하거나 실례가 되는 거짓은 피한다.
5. **결과 미리보기 → 수정 → 승인** (아래 5.6 참조)

**B. 명리학 기반 나의 풀이 (선택)**
- 입력: 생년월일, **음력/양력 구분**, 태어난 시간(모름 선택 가능), 필요 시 윤달 여부.
- 관리자 지침에 따라 명리학 기반으로 **약 1페이지 분량**의 "나에 대한 글"을 생성한다.
- **선택 사항**: 입력 화면에 "입력하지 않으셔도 됩니다"를 눈에 띄게 보여 주고 **건너뛰기** 버튼을 둔다. 건너뛰어도 불이익이 없다.
- 생년월일과 태어난 시간 원본은 **풀이 생성에만 사용**하고, 소개 페이지, 프로필, 다른 회원 화면, 관리자 화면에 **절대 노출하지 않는다.** 서버에도 풀이 생성 직후 삭제하거나 저장하지 않는 것을 기본값으로 한다.
- 기본 지침: 재미와 자기이해 목적의 참고용 글로 작성하고, 건강·재산·수명·질병 등 단정적이거나 민감한 예언은 쓰지 않는다.

**C. 사전 추측**
- 승인된 모든 소개 페이지를 별칭으로만 목록에 보여 준다. 본인 글은 제외한다.
- 페이지마다 **참석자 명단에서 클릭 한 번**으로 "누구일 것 같은지" 선택한다(검색 없이 명단 리스트 선택). 마감 전까지 수정 가능.
- 관리자 설정으로 "졸업여행 참석자만 후보에 포함" 옵션을 둔다.

**D. 현장 진행 (사회자 화면 + 회원 휴대폰)**
1. 사회자가 소개 페이지를 하나 연다(별칭 상태).
2. 사전 추측 결과(누가 누구를 몇 표로 골랐는지)를 보여 준다.
3. 당사자가 휴대폰에서 **"저예요" 버튼**을 누르면 사회자 화면에 이름이 공개된다(사회자가 대신 공개할 수도 있음).
4. 이어서 그 사람의 **2진실 1거짓** 페이지가 열린다.
5. 모든 회원이 **동시에 자기 휴대폰**에서 거짓을 선택한다. 본인 차례는 투표할 수 없고, 1인 1회, 마감 후 변경 불가.
6. 사회자가 투표를 마감하고 **정답과 정답자 목록**을 공개한다.
7. 다음 사람으로 넘어간다. 순서는 사회자가 지정하거나 랜덤.

**E. 점수와 시상**
- 누적 점수를 두 가지로 집계한다: A) 누구인지 가장 많이 맞힌 사람, B) 거짓을 가장 많이 맞힌 사람.
- 각 부문 1위, 총 **2명**에게 선물한다.
- **동점자가 여러 명이면** 사회자가 **동점자만 표시된 룰렛**을 화면에 띄워 돌린다(애니메이션, 결과 확정 화면 포함).

### 5.3 활동 ② 나의 고민은?

**사전 작성**
- 사전 작성 마지막 단계(또는 별도 메뉴)에서 **고민 또는 조언을 구하고 싶은 질문**을 작성한다.
- 작성 시 **익명/실명 여부를 미리 선택**한다. 카테고리(경영 / 인재 / AI 도입 / 가족·건강 / 기타)도 고른다.
- 마감 전까지 수정·삭제 가능.

**현장 진행**
1. 사회자가 **"고민 뽑기"** 를 열면 **로또 번호 뽑기처럼** 화면이 돌아가는 연출이 나오고 고민 하나가 뽑힌다. 카테고리를 지정해 뽑는 옵션도 둔다.
2. 뽑힌 고민의 **내용만** 화면에 크게 표시한다(작성자 숨김).
3. 약 **15분(설정 변경 가능)** 동안 대화한다. 화면에 **타이머**를 크게 보여 주고 일시정지, 연장, 건너뛰기를 지원한다.
4. 시간이 끝나면 **"이름 오픈"** 버튼이 뜨고, 사회자가 누르면 실명 작성자는 **이름**, 익명 작성자는 **"익명"** 이 표시된다. 익명 작성자가 원하면 본인이 직접 밝힐 수 있다.
5. 다음 뽑기에서는 **이미 나온 고민을 제외**하고 뽑는다.
6. 보통 6~8개 진행하고, 시간이 지나면 중단했다가 식사나 다른 활동 뒤에 **이어서** 진행할 수 있다(진행 상태 저장).
7. 선택 기능: 고민이 뽑히면 AI가 **관점 3가지**를 짧게 제시해 대화의 마중물로 쓴다(사회자가 켜고 끌 수 있음).

### 5.4 활동 ③ 타임캡슐

**팀 구성**
- 관리자가 팀 수 또는 팀당 인원(4~5명 권장)을 입력하면 **랜덤으로 팀을 구성**한다.
- 선택 옵션: 연령대(관리자가 회원별로 입력)를 고려해 세대가 섞이도록 구성.
- 결과는 수동으로 조정할 수 있고, 큰 화면에 팀 구성 결과를 보여 줄 수 있어야 한다.

**작성 내용**
- **나의 1년 뒤 목표**: 개인이 작성, 본인만 볼 수 있다.
- **팀 약속 2가지**: 팀원이 함께 작성한다. 저장 시 **팀명과 팀 구성원**이 함께 저장된다.

**봉인과 열림**
- 관리자가 열림 일시를 등록하기 전에는 **누구도 내용을 볼 수 없다.** 작성 직후 본인 확인 가능 여부는 관리자 설정으로 선택한다(기본값: 완전 봉인).
- 내년 송년회 일정이 정해지면 **관리자가 열림 날짜와 시간을 등록**한다. 등록 전에는 "아직 열리지 않았어요"만 표시한다.
- **봉인은 서버에서 보장한다.** 열림 일시 전에는 API가 해당 내용을 **응답으로 내려주지 않는다**(화면에서 숨기는 방식은 불가). 시각 비교는 서버 시각 기준(Asia/Seoul)으로 한다.
- 열림 시각이 되면 개인 목표와 팀 약속이 열리고, 모두 모여 함께 확인한다.
- 열림 일시 변경 기록을 남기고, 열림 전에는 관리자도 내용을 열람할 수 없다.
- 1년 이상 데이터를 보관한다(백업 필수).

### 5.5 회원 프로필 북

- 전체 회원 명단을 등록하고, **졸업여행에 불참하는 회원도 명단에 포함**한다.
- 활동에 참여한 회원은 AI가 활동 내용을 바탕으로 만든 **프로필 페이지**가 자동 등록되고, **로그인한 모든 회원**이 다른 회원의 프로필을 열람할 수 있다.
- 프로필에 담기는 것은 회원이 **공개로 승인한 소개 내용(및 승인한 풀이 글)** 뿐이다. **2진실 1거짓 문제, 비공개 항목, 고민, 타임캡슐, 생년월일 원본은 포함하지 않는다.**
- 미참여 회원은 "미작성"으로 표시하고, 나중에 본인이 링크로 작성할 수 있다.
- 행사 종료 후 별칭 대신 **실명**으로 프로필을 보여 준다(관리자가 공개 시점을 설정).
- 본인은 언제든 수정·삭제할 수 있다.

### 5.6 결과 미리보기 · 수정 · 승인 (공통 규칙)

적용 대상: 소개 페이지, 2진실 1거짓, 명리 풀이.

1. 생성 결과를 **먼저 채팅창에서 보여 준다.**
2. 회원이 수정 요청을 하면(예: "더 짧게", "말투를 부드럽게") AI가 **요청한 방향대로 고쳐서** 다시 보여 준다. 반복 가능.
3. 회원이 **"최종 배포하겠습니다"** 버튼으로 승인한 결과만 DB에 **공개 상태로 저장**되어 활동과 프로필에 반영된다. 승인 전 초안은 다른 회원과 관리자에게 보이지 않는다. 승인 후에도 승인 취소와 재수정이 가능하다.
4. **지침 검증**: 수정 요청이 관리자 지침에 맞지 않는 경우(신원이 드러나는 정보를 넣어 달라는 요청, 생년월일 원본 노출 요청, 지침이 금지한 단정적 예언 등)에는 AI가 **"관리자 지침에 맞지 않아 반영할 수 없습니다"** 라고 이유를 짧게 알리고 **수정에 반영하지 않는다.** 지침에 맞는 다른 방향의 수정은 계속 돕는다.
5. 항목별 공개 범위를 선택할 수 있다: **소개 페이지에 공개 / 2진실 1거짓 문제용으로만 사용 / 사용 안 함.**
6. 서버 측에서도 승인된 결과에 금지 항목(이름, 회사명 등)이 포함되지 않았는지 한 번 더 검사한다.

## 6. 기술 스택 (Vercel 배포 기준)

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | **Next.js (App Router) + TypeScript** | Vercel 기본 지원 |
| 스타일 | Tailwind CSS | 모바일 우선 |
| DB | **Supabase Postgres** (또는 Vercel Marketplace의 Neon) | 무료 플랜으로 충분 |
| 실시간 동기화 | **Supabase Realtime** (Postgres Changes 또는 Broadcast) | Vercel 서버리스는 WebSocket 서버를 직접 운영할 수 없으므로 외부 실시간 서비스를 쓴다 |
| AI | **Anthropic Claude API**(서버에서만 호출) | 인터뷰, 요약, 풀이, 수정, 지침 검증 |
| 음성 | Web Speech API(`ko-KR`) + 폴백 | iOS Safari 지원이 제한적이므로 폴백 필수 |
| 인증 | 서명된 쿠키 세션(`jose`) | 소셜 로그인 불필요 |
| 호스팅 | **Vercel** (프로젝트 1개, 리전 `icn1` 서울) | |

**주의**
- Vercel 서버리스 함수는 실행 시간 제한이 있다. AI 응답은 **스트리밍**(Route Handler + SSE)으로 보내고, 함수의 `maxDuration`을 설정한다.
- 서버 메모리나 파일 시스템에 상태를 두지 않는다. 모든 상태는 DB에 저장한다.
- 동기화가 안 될 때를 대비해 **2~3초 폴링 폴백**을 둔다.

```
members        id, name, age_group?, role('member'|'admin'), trip_days(text[]) , trip_label(bool),
               consent_at, created_at
profiles       id, member_id(unique), alias, intro_md, intro_status('none'|'draft'|'approved'),
               public_fields(jsonb), reading_md?, reading_status, approved_at, updated_at
interviews     id, member_id, messages(jsonb), turn_count, updated_at       -- 채팅 원본, 본인 외 열람 불가
truth_lies     id, member_id, statements(jsonb[3]), lie_index, status, approved_at
guesses        id, guesser_id, target_member_id, chosen_member_id, created_at   -- 사전 추측
votes          id, round_id, voter_id, chosen_index, created_at                 -- 거짓 투표
rounds         id, target_member_id, state('hidden'|'revealed'|'voting'|'closed'), order_no
worries        id, member_id, body, category, anonymous(bool), drawn_at?, order_no?
worry_session  id, current_worry_id?, timer_ends_at?, paused(bool)

capsule_teams  id, name, member_ids(uuid[])
capsule_pacts  id, team_id, pacts(jsonb[2]), created_at
```

- 타임캡슐 본문(`body_enc`, `pacts`)은 서버 사이드 접근만 허용하고, 열림 일시 이후에만 API가 반환한다. 필요하면 서버 키로 암호화해 저장한다.
- 클라이언트에서 DB에 직접 접근하지 않는다(모든 민감 읽기·쓰기는 Route Handler 경유). Supabase RLS는 기본 거부로 둔다.
- 생년월일 원본은 저장하지 않는 것을 기본값으로 한다.

## 8. API (Route Handlers 초안)

- `POST /api/interview/message` (스트리밍), `POST /api/interview/finalize`
- `POST /api/reading` (명리 풀이 생성, 원본 미저장)
- `POST /api/revise` (수정 요청 + 지침 검증), `POST /api/approve`

- `POST /api/guesses`, `GET /api/guesses/summary`
- `POST /api/rounds/[id]/{reveal|open-vote|close}`, `POST /api/votes`
- `POST /api/worries`, `POST /api/worry/draw`, `POST /api/worry/timer`, `POST /api/worry/reveal`
- `POST /api/capsule/teams/generate`, `POST /api/capsule/goal`, `POST /api/capsule/pact`, `GET /api/capsule/open`
- `POST /api/admin/lottery` (동점자 룰렛), `GET /api/admin/export` (전체 백업)
- 관리자 API는 서버에서 역할을 검증한다.

## 9. AI 프롬프트 구성

- **관리자 지침(DB의 `settings`)** 을 모든 AI 호출의 system prompt에 포함한다. 지침 항목: 질문 주제, 말투, 금지 사항(신원 정보, 단정적 예언), 분량(소개 2페이지, 풀이 1페이지), 후속 질문 상한.
- 호출 종류: 인터뷰 질문 생성, 소개 페이지 생성, 2진실 1거짓 생성, 명리 풀이, 수정 반영, **지침 적합성 판정**(수정 요청이 지침에 맞는지 먼저 판정한 뒤 반영).
- 모델은 환경변수(`ANTHROPIC_MODEL`)로 바꿀 수 있게 한다.
- 모든 호출은 서버에서만 하고, API 키는 클라이언트에 노출하지 않는다.
- 호출 실패 시 재시도 1회 후 **수동 입력 모드**(AI 없이 직접 소개글, 거짓 항목 작성)로 전환한다.

## 10. 관리자 화면

- 회원 명단 등록·수정(CSV 붙여넣기 지원), 졸업여행 참석 현황 보기
- 필수 질문, AI 관리자 지침, 초대코드, 단계별 시작·마감 일시 설정
- 현장 진행 컨트롤: 소개 열기, 추측 결과, 이름 공개, 투표 열기·마감, 정답 공개, 다음 사람, 점수판, 동점자 룰렛
- 고민 뽑기 시작, 타이머 조정, 이름 오픈, 진행 상태 저장·재개
- 팀 구성, 타임캡슐 열림 일시 등록
- 전체 데이터 **내보내기(JSON/CSV)**
- 사회자 조작은 큰 버튼 중심으로 단순하게 만들고, 투표 현황은 실시간으로 보여 준다.

## 11. 비기능 요구사항

- **동시 접속 20명**에서 지연이 없어야 한다(투표 반영 2초 이내).
- 초기 로딩 가볍게(이미지 최소화, 번들 크기 관리). 행사장 와이파이가 약해도 동작해야 한다.
- 보안: 환경변수로 비밀 관리, 관리자 API 서버 검증, 입력값 검증(zod 등), 로그에 개인 답변 원문을 남기지 않는다.
- 개인정보: 공개 범위는 본인 선택대로만 적용하고, 본인이 수정·삭제할 수 있어야 한다.
- 시간대는 **Asia/Seoul** 기준.

## 12. Vercel 배포 체크리스트

**환경변수**

| 이름 | 용도 |
|---|---|
| `ANTHROPIC_API_KEY` | AI 호출 |
| `ANTHROPIC_MODEL` | 사용할 모델 |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | 서버에서 DB 접근 |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Realtime 구독 전용 |
| `SESSION_SECRET` | 세션 쿠키 서명 |
| `ADMIN_PASSCODE` | 관리자 로그인 |
| `INVITE_CODE` | 회원 초대코드(초기값, 이후 관리자 화면에서 변경) |

**배포 순서**
1. GitHub에 저장소를 만들고 Vercel에 연결한다.
2. Supabase 프로젝트를 만들고 마이그레이션(SQL)을 실행한다.
3. Vercel 환경변수를 등록한다(Production/Preview 구분).
4. 함수 리전을 서울(`icn1`)로 설정하고 AI 라우트의 `maxDuration`을 늘린다.
5. 배포 후 **프로덕션 URL로 QR코드**를 만든다(도메인을 고정해 두면 좋다).
6. 리허설: iPhone/Android 각각에서 접속, 음성 입력, 동시 투표를 확인한다.

## 13. 구현 순서 (단계별로 하나씩)

1. 프로젝트 세팅, 디자인 토큰, 공통 레이아웃, DB 스키마, 로그인(회원·관리자)
2. 회원 명단, 졸업여행 팝업(날짜 중복 선택), 개인정보 동의
3. AI 인터뷰 채팅(스트리밍) + 음성 입력 + 금지 규칙
4. 결과 생성 → 미리보기 → 수정 → 승인 → 지침 검증
5. 명리 풀이(선택, 원본 미저장)
6. 프로필 북, 사전 추측
7. 사회자 현장 진행(공개, 투표, 점수판, 룰렛) + 실시간 동기화
8. 나의 고민은?(뽑기 연출, 타이머, 이어서 진행)
9. 타임캡슐(팀 구성, 작성, 서버 봉인과 열림)
10. 관리자 설정 화면, 백업 내보내기
11. 부하 테스트(20명 동시), 오류 대비 수동 모드, 접근성 점검, 배포

각 단계가 끝날 때마다 로컬에서 동작을 확인하고, 다음 단계로 넘어가기 전에 요약해 달라고 요청하세요.

## 14. 인수 조건 (테스트 체크리스트)

- [ ] QR로 접속해 이름과 초대코드만으로 로그인된다.
- [ ] 졸업여행 팝업에서 11일과 12일을 동시에 선택할 수 있고, 참석안함과는 배타적이다.
- [ ] 음성 버튼으로 말하면 텍스트로 변환되어 채팅창에 보인다(미지원 기기는 안내 표시).
- [ ] 이름·회사명 등 신원 정보가 소개글에 남지 않는다.
- [ ] 명리 풀이는 건너뛸 수 있고, 생년월일 원본이 어디에도 노출·저장되지 않는다.
- [ ] 승인하지 않은 초안은 다른 회원에게 보이지 않는다.
- [ ] 지침에 맞지 않는 수정 요청은 거절 이유와 함께 반영되지 않는다.
- [ ] 20명이 동시에 투표해도 2초 안에 집계가 갱신된다.
- [ ] 동점자 룰렛이 동점자만으로 동작한다.
- [ ] 고민 뽑기는 이미 나온 고민을 제외하고, 익명 고민은 이름 오픈 전까지 작성자가 보이지 않는다.
- [ ] 타임캡슐은 열림 일시 전에 API 응답에 내용이 포함되지 않는다(개발자 도구로도 확인 불가).
- [ ] 미참석 회원도 명단에 있고 "미작성"으로 표시된다.
- [ ] 관리자가 전체 데이터를 내려받을 수 있다.

## 15. 열린 질문 (구현 전에 확인)

- 풀이 기본 지침의 금지 범위(기본값: 건강·재산·수명·질병 단정 금지)
- 운영 도메인(커스텀 도메인 사용 여부)
